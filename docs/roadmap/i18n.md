# Internationalisation (Bangla first)

`Status: 📋 planned · Phase 4 · Difficulty: intermediate`

Translate the app, render every script correctly, and let teachers make lessons in their own language, starting with Bangla.

## Goal

Rupok is built for teachers who often teach in languages other than English.
This plan makes the UI translatable, ships a complete Bangla translation
first, makes sure Bangla (and later Arabic, Devanagari, Tamil…) renders
correctly everywhere text appears, and lets AI agents produce lessons and
Smart Objects in the teacher's language.

## User story

- *As a Bangla-medium teacher*, I switch the app to বাংলা and every menu, tool
  name and message is in Bangla, with Bangla digits if I want them.
- *As a teacher*, I type Bangla text on a slide and conjuncts (যুক্তাক্ষর) and
  vowel signs (ি, ে, ৌ) are shaped correctly on screen, in thumbnails and in
  exports, even on a school PC with no Bangla font installed.
- *As a teacher*, I ask my AI agent for a Bangla quiz about the water cycle and
  the Smart Object validates and displays correctly.
- *As a volunteer translator*, I can translate Rupok into Tamil in a web UI
  without touching code.

## Scope

- UI string extraction and a translation runtime in `apps/board`.
- Bangla (`bn`) translation, plural rules, number and date formatting.
- Offline fonts with Bangla coverage for the UI, text items and Smart Object
  theme fonts.
- Correct shaping in any Rust-side text rendering (thumbnails, exports).
- Lesson language metadata and agent/skill guidance for non-English content.
- A translation workflow for contributors.

## Non-goals

- Translating lesson content automatically (teachers' agents can do that).
- Full right-to-left UI in this phase (prepare with CSS logical properties;
  RTL ships with the first RTL language).
- Localising the specs and contributor docs.

## Design

### UI strings (`apps/board`)

- Catalog files `apps/board/src/i18n/<lang>.json` (new), flat keys
  (`"toolbar.pen": "Pen"`), ICU MessageFormat for plurals and variables
  (`"pages.count": "{n, plural, one {# page} other {# pages}}"`).
- Tiny runtime `apps/board/src/i18n/index.ts` (new): `t(key, vars?)`,
  `locale()` signal, lazy-loads the catalog, falls back to English per key.
  Use `Intl.PluralRules`, `Intl.NumberFormat`, `Intl.DateTimeFormat`; for `bn`,
  digits follow a user setting (`latn` or `beng` numbering system).
- A lint script (`apps/board/scripts/i18n-check.ts`, new) fails CI on missing
  keys in `en.json`, unused keys, and hard-coded user-visible strings in TSX
  (simple AST check).
- Locale choice: OS/browser language by default, override in settings
  (persisted with the existing prefs in `apps/board/src/state.ts`).

### Fonts

- Bundle open-licensed fonts (SIL OFL) offline: Noto Sans Bengali (UI and
  text items) plus Noto Sans for Latin; keep them in the app bundle, not
  fetched from the network.
- Text items are currently rendered by the DOM layer (`Engine::dom_items_json`
  → UI), so browsers shape them with their own text engine (HarfBuzz in
  Chromium/WebView2). The task here is only font availability: add the bundled
  font to the text item's CSS `font-family` stack.
- The host passes Bangla-capable fonts to Smart Objects through theme tokens
  (`font.body`, `font.heading`), so objects inherit them
  (`spec/smart-object.md#theme`). No spec change: tokens are strings.

### Shaping in Rust (thumbnails, exports, future GPU text)

Any Rust-side text rendering (page thumbnails `thumbs/<n>.png`, MP4 export,
headless exports via `rupok-render`) must use a real shaper. Drawing one glyph
per code point breaks Bangla: conjuncts need ligature substitution, the vowel
sign ি is displayed before the consonant it follows in memory, and reph/ya-phala
need positioning. Proposed: `cosmic-text` (or `parley`) with `swash`
rasterisation, both pure Rust and wasm-compatible, fed with the bundled fonts.
This applies to new code only; the GPU ink renderer draws no text today.

### Lesson language (proposed; requires an RFC)

- Add optional `meta.lang` (BCP-47, e.g. `"bn"`) to `doc.loro`
  (`spec/rupok-format.md`, section "meta") and optionally `lang` to
  `manifest.json` for search. Additive, no version bump; **requires an RFC**.
- Text items inherit `meta.lang` for the DOM `lang` attribute (better font
  selection and hyphenation).

### Smart Objects and agents

- Skill and agent docs (`skills/`) tell agents to set `<html lang="bn">`, use
  the theme font tokens, and keep the 24 px minimum (Bangla glyphs need it).
- Validator bug to fix first: `remote_resources` in
  `crates/rupok-format/src/object.rs` slices a fixed 48-byte window and panics
  when a multi-byte character straddles it, so `validate()` can crash on
  Bangla objects that contain `//` (see `spec/smart-object.md`, "Conformance
  notes"). Fix with `str::floor_char_boundary` or byte-slice matching, and add
  a regression test with Bangla text.
- MCP tools (`crates/rupok-cli`): `create_lesson` accepts an optional `lang`.

### Translation workflow

- Host translations on a libre platform (Weblate) connected to the repo;
  English is the source; PRs from Weblate are reviewed like code.
- `docs/translating.md` (new): how to add a language, style guide (formal vs
  informal address, keep terms consistent with school textbooks).

## Implementation tasks

1. Fix the validator multi-byte panic in `remote_resources` + Bangla regression test (needs a Rust change by a maintainer). (good-first-issue)
2. i18n runtime (`t`, locale signal, ICU plurals via `Intl`) with unit tests. (intermediate)
3. Extract all UI strings in `apps/board` into `en.json` (split by component; one PR per area). (good-first-issue)
4. `i18n-check` script in CI. (good-first-issue)
5. Bangla translation of the full catalog, reviewed by two teachers. (good-first-issue)
6. Bundle Noto Sans Bengali; font stacks for UI, text items and Smart Object theme tokens. (good-first-issue)
7. Number/date formatting with the `bn` digits setting. (good-first-issue)
8. RFC + core support for `meta.lang`; set `lang` on text items in the DOM. (intermediate)
9. Rust shaping stack for thumbnails/exports (`cosmic-text` + `swash`), with a golden-image test of Bangla conjuncts. (advanced)
10. Weblate setup and `docs/translating.md`. (good-first-issue)
11. CSS logical properties audit for future RTL. (intermediate)

## Acceptance criteria and tests

- Switching to বাংলা translates 100 % of UI strings (CI check: no missing keys
  in `bn.json`).
- On a clean Windows 10 and Ubuntu VM with no Bangla fonts installed, Bangla
  text items render with correct conjuncts (visual check against a reference
  screenshot of "ক্ষ, স্ত্র, কি, কৌ, র্ক").
- `ObjectBundle::validate()` never panics on non-ASCII input (property test
  with random Unicode text around `//` and URLs).
- The Bangla quiz generated by an agent following `skills/` validates with zero
  errors and displays correctly at 960×540.
- Golden-image test for Rust-shaped Bangla thumbnails (once task 9 lands).

## Performance budget

- Catalog load ≤ 20 KB gzipped per language, loaded lazily.
- Bundled fonts add ≤ 1 MB to the installer (subset if needed).
- No effect on pen latency or `rupok-bench` budgets.

## Open questions

- Bangla digits by default for `bn`, or Latin digits (common in ICT classes)?
- Which second language after Bangla? Ask the teacher community (Hindi, Urdu,
  Arabic, Indonesian are candidates; Urdu/Arabic require the RTL work).
- Should lesson language drive the AI agent's language automatically through
  MCP?
